## DES-01 — MEDIUM / UNDER / Under-building: missing seam in the ADR-004 measurement contract (chart key vs source_file)

- **Location:** plans/graficos-hidreletricos/epic-02-hydro-flow-charts/ticket-005-remove-stale-count-text.md:71-75, 111-114, 139-146 (realizes ADR-004, 00-master-plan.md:136-150)
- **Evidence:** ADR-004 and R22 say every count is 'measured through enabled_specs()/all_specs()'. Ticket-005 applies that rule to the FALLBACK_UNITS counts using chart keys. Target state: 'enabled keys: `len({s.key for s in enabled_specs()})`'. Measuring script: `e=list(dict.fromkeys(s.key for s in enabled_specs())); print(len(e), len(F)-len(e), e)`, followed by 'If the measurement differs from 26 and 16, use the measured values'. AC1 compares the dict's enabled prefix with `dict.fromkeys(s.key for s in enabled_specs())`. But FALLBACK_UNITS is keyed by source_file. specs.py:62-71 (`_scalar_series` takes unit from `FALLBACK_UNITS[source_file]`, 'Its key is distinct from source_file') and tests/test_schemas.py:25-48 (the enabled partition holds `CUSTOS` and `TEMPO`, not `CUSTO_PRESENTE`/`TEMPO_*`) both show this. After ticket-004, enabled_specs() returns 31 keys (24 series plus 7 scalar chart keys), so the script prints 31 and 42-31=11, not 26 and 16. AC1 cannot be met: no dict key equals `CUSTO_PRESENTE`. The correct measure is `dict.fromkeys(s.source_file for s in enabled_specs())`, which gives 26.
- **Impact:** An implementer who follows the plan's 'measure, never copy' rule writes 'Covers the 31 keys enabled by default plus the 11 disabled' into the schemas.py comment. No test checks that comment, so R25's cleanup puts a new false count into src. Applied to `_ENABLED_CHART_KEYS` instead, the same measure produces 31 keys including CUSTO_PRESENTE. That breaks `set(_ENABLED_CHART_KEYS) <= set(FALLBACK_UNITS)` and contradicts AC2's '26 entries', so the ticket stalls or needs a CLARIFICATION round. The bug lands in the one ticket whose whole purpose is removing wrong counts.
- **Defender verdict:** **ACKNOWLEDGED** — The finding is correct, and the measuring script has a second defect the attacker did not mention. Ticket-005's Background (lines 20-21) gets the target right: 26 = 24 SERIES keys + CUSTOS + TEMPO. That count is per source_file. But the three places that turn this into a measurement all use chart keys: the Target state formula (line 74, `len({s.key for s in enabled_specs()})`), AC1 (lines 111-112, `dict.fromkeys(s.key for s in enabled_specs())`) and the measuring script (lines 140-142). FALLBACK_UNITS is keyed by source_file. specs.py:49-72 (`_scalar_series`, unit=FALLBACK_UNITS[source_file], 'Its key is distinct from source_file') shows this, and tests/test_schemas.py:25-50 lists CUSTOS and TEMPO, not CUSTO_*/TEMPO_*. I measured it on main through dessem_dashboard.charts.registry. enabled_specs() gives 28 distinct keys: 21 series plus CUSTO_PRESENTE, CUSTO_FUTURO, CUSTO_TOTAL, TEMPO_MILP, TEMPO_PL, TEMPO_LEITURA and TEMPO_TOTAL. All seven scalar keys are missing from FALLBACK_UNITS. The same specs give only 23 distinct source_files. Ticket-004 adds three SERIES specs, so the script would print 31 and 11 where the plan expects 26 and 16. Line 145 ('If the measurement differs from 26 and 16, use the measured values') would then tell the implementer to write 31/11. AC1 cannot be met, because no FALLBACK_UNITS key equals CUSTO_PRESENTE. Second defect: line 140 imports `enabled_specs, all_specs` from `dessem_dashboard.charts.specs`. That raises ImportError (I reproduced it), because both functions live in `dessem_dashboard.charts.registry` (registry.py:123-130). So the measurement the ticket requires cannot run as written either. The door is two-way, but no ticket schedules a fix, and an unmeetable acceptance criterion blocks the ticket.
- **Backlog entry:** Severity: major. Problem: ticket-005 measures the FALLBACK_UNITS enabled count by chart key (`s.key`), but the dict is keyed by `source_file`. Its measuring script also imports enabled_specs/all_specs from the wrong module. Impact: the script raises ImportError. Once the import is fixed, it gives 31/11 instead of 26/16, and line 145 tells the implementer to write those wrong numbers into the schemas.py comment. AC1 cannot be met (CUSTO_PRESENTE and the other scalar keys are not FALLBACK_UNITS keys), so the ticket stalls or ships a new stale count. Resolution Direction: in ticket-005, change lines 74, 112 and 142 to `dict.fromkeys(s.source_file for s in enabled_specs())` and change the import on line 140 to `dessem_dashboard.charts.registry`. Add an `assert set(e) <= set(F)` check to the script, and state in Technical Details that FALLBACK_UNITS is keyed by source_file (specs.py `_scalar_series`). Estimated Effort: low.

## DES-02 — MEDIUM / UNDER / Under-building: dessem-specialist sign-off corrections left out of the ADRs and the README chain contract

(b) ADR-003's claim that plain sums 'double-count cascade water' is false for QINC. (c) ADR-006's rework trigger points at inequality form (c), QAFL >= QINC, which 'may fail at a reservoir that a pumping station draws from' and needs exclusions. A grep for Sobradinho, regulari, dadvaz and pumping over the plan finds these only in signoff.md and the brief. ADR-003 line 131 still says 'Plain sums over plants are aggregate indicators that double-count cascade water'. ADR-006 line 185 still says 'using only the inequality forms recorded in the dessem brief', and the brief (dessem-specialist.brief.md:20, :42) still states form (c) and C1 without the caveats. The doc brief (open-source-documentation-writer.brief.md:48) says it takes its README semantics wording from the dessem brief. The python and test-strategist sign-off notes, by contrast, were folded into tickets 002, 005 and 006.
- **Impact:** The plan's recorded contracts are the versions the specialist marked incorrect. ADR-006's rework path tells a future synthesis-property module to assert QAFL >= QINC without the pumping exclusion, so that module would false-fail on decks with pumping. The corrections exist only in a sign-off file that no ticket cites.
- **Defender verdict:** **ACKNOWLEDGED** — The evidence supports the finding. signoff.md:30-43 records the dessem-specialist's three corrections: (a) QINC is not 'natural' at regularized-inflow plants such as Sobradinho, where QAFL == QINC; (b) plain sums do not double-count QINC; (c) QAFL >= QINC is an equality at regularized-inflow plants and may fail at pumping-origin reservoirs (MM eq. 9.7). The operator resolution (signoff.md:117-119) forwards these to the same REVISION dispatch. They never landed. I grepped the plan for sobradinho, regulari, dadvaz, pumping, itp=3 and natural, outside signoff.md and the dessem brief, and found nothing. The master plan is unchanged at these points: line 131 (ADR-003) still says plain sums 'double-count cascade water'; line 185 (ADR-006 rework_trigger) still points to 'the inequality forms recorded in the dessem brief', and the brief at line 20 (form c) and line 42 (C1, 'natural incremental inflow', 'Vazão Afluente = incremental + upstream outflows') still has no caveats; line 344 says the dessem contracts, C1 among them, are 'embedded'. The doc brief consumes this wording directly (open-source-documentation-writer.brief.md:14 'worded by the dessem seat', :48). Ticket-009's outline (lines 13-24) and epic-03's 'Learnings to collect' (00-epic-overview.md:32-37) do not mention the amendment, and ticket-009 has no dessem review step. The other seats' sign-off notes were applied: ticket-002 states the `_load_registries(..., *, fictitious_codes)` signature, ticket-005 owns the FALLBACK_UNITS regroup, and ticket-006:66 applies the payload.py:159 subtitle rule. So only the dessem seat's corrections were dropped. ADR-003 and ADR-006 are two-way doors, but no ticket schedules the wording fix, so the rubric's UNDER defense does not apply.
- **Backlog entry:** Severity: major. Problem: the dessem-specialist's sign-off corrections (signoff.md:30-43: C-SEM QINC/QAFL wording at regularized-inflow plants, ADR-003's QINC double-count wording, and the caveats on ADR-006's form (c)) were forwarded to revision but appear in no ADR, contract or ticket. Impact: ticket-009 is refined just in time from the uncorrected C1, so the README may call QINC 'natural' everywhere and state QAFL = QINC + upstream outflows at Sobradinho. That is a DESSEM-semantics error in a user-facing reference. ADR-006's rework path would also lead a future synthesis-property module to assert QAFL >= QINC without the pumping-origin exclusion. Resolution Direction: (1) Fix ADR-003's rejected-option durability text: the double counting applies to QAFL/QDEF/QTUR/QVER, not QINC. (2) Rewrite ADR-006's rework_trigger to cite form (c) with both caveats (an equality at regularized-inflow plants; exclude or verify pumping-origin reservoirs, MM eq. 9.7). (3) Record an amended C1 ('C-SEM, amended at sign-off') in the master plan or the dessem brief. (4) Add the amendment to ticket-009's Anticipated Scope and epic-03's learnings, and require a dessem-specialist review, or at least a citation of signoff.md:30-43, when ticket-009 is refined. Estimated Effort: low.

## DES-03 — LOW / OVER / Over-building: catalogue-coupled docs-drift guard that no requirement asks for

- **Location:** plans/graficos-hidreletricos/epic-02-hydro-flow-charts/ticket-008-checklist-section-10-guard-test.md:38-49, 77-92; contrasts with 00-master-plan.md:188-204 (ADR-007) and 00-master-plan.md:216-218 (ADR-008)
- **Evidence:** ADR-007 says section 10 is 'guarded by a static test like sections 8 and 9'. Those guards pin literal strings only: test_renderer_contract.py:532-568 and test_charts_filters.py:652-660, and test_renderer_contract.py imports no enabled_specs. Ticket-008 instead requires 'Read the titles from enabled_specs(), filtered by level, instead of writing them out. The test then follows the catalogue', plus an ordering check over those titles. That is a docs-drift test, checklist against registry. ADR-008 rejected exactly this kind of test for the README: 'drift-proof-readme-with-docs-test ... not asked for by R24/R28 (over-engineering)'. The doc brief made the same call (open-source-documentation-writer.brief.md:22). R20 and ADR-007 ask only that section 10 cannot be silently deleted.
- **Impact:** test_renderer_contract.py becomes a new, unlisted pin site for every UHE-level catalogue change. Four UHE specs ship disabled (VARMI_UHE, VARPI_UHE, VAGUA_UHE, VCALHA_UHE). Enabling one, or retitling or reordering a UHE chart, makes `section.index(title)` raise in the checklist guard. That forces a rewording of section 10, which ADR-007's one-way framing treats as frozen. Ticket-009's pin-table scope is 'the files measured from tickets 003-005', so the README pin table this plan produces leaves this file out. A test the bar classes as unrequested complexity becomes a recurring surprise at the next chart change.
- **Defender verdict:** **ACKNOWLEDGED** — The core claim holds, but the attacker overstates the impact. Confirmed: ADR-007 (master plan lines 188-204) asks for a guard 'like sections 8 and 9', and those guards pin literal strings only (test_renderer_contract.py:532-568; test_charts_filters.py:652-660; test_renderer_contract.py imports nothing from charts.registry). Ticket-008 (lines 48-49, 89-91) instead derives the UHE titles from enabled_specs() and checks their order. That turns the guard into a checklist-versus-catalogue drift check, and no ADR records the choice. It also conflicts with the plan's own position, since ADR-008 (lines 216-218) rejects a docs-drift test as 'not asked for (over-engineering)'. R20 and ADR-007 only need section 10 to be undeletable, and pinned literal titles would meet that at the same cost. Confirmed by measurement: four UHE specs ship disabled (VARMI_UHE 'Volume Armazenado Inicial (hm3)', VARPI_UHE, VAGUA_UHE, VCALHA_UHE). Enabling any of them, or retitling a UHE chart, makes `section.index(title)` raise ValueError in test_renderer_contract.py. Ticket-009's pin-table scope (line 21-22, 'files measured from tickets 003-005' plus the `_ENABLED_CHART_COUNT` grep) would not list this file. Overstated: the claim that this rewording 'is frozen' by ADR-007 is wrong. ADR-007's one-way door covers steps 1-32 only, as the title says and as the operator's narrowing confirms (signoff.md:115), and section 10 is steps 33+, so the edit a future failure forces is allowed. The failure also flags real staleness in step (d). The added complexity is small, which is why this is minor. Still, I can cite no requirement that makes catalogue coupling necessary, and it adds an unlisted pin site, so under the rubric this is not defensible as written.
- **Backlog entry:** Severity: minor. Problem: ticket-008 derives the section-10 guard's UHE titles from enabled_specs(). That makes the guard an unrecorded checklist-versus-catalogue drift test, departing from ADR-007's 'like sections 8 and 9' literal-pin pattern and from ADR-008's rejection of docs-drift tests. Impact: tests/test_renderer_contract.py becomes a new pin site for every UHE catalogue change (enabling VARMI/VARPI/VAGUA/VCALHA_UHE, or a retitle or reorder), and ticket-009's README pin table, scoped to tickets 003-005, will not list it, so the next chart change fails there unexpectedly. Resolution Direction: choose one. (a) Pin the section-10 titles as literals, like the section 8/9 guards, and drop the enabled_specs() read. (b) Keep the catalogue coupling, but record it in ADR-007 as a deliberate drift check and add test_renderer_contract.py, with the reason, to ticket-009's pin-table scope. With either option, resolve the duplicate-title issue the sketch already notes ('Geração' and 'Defluência'/'Turbinamento'/'Vertimento' also occur in the SIN step) by searching from the UHE step's position. Estimated Effort: low.
